# INT959 — Supplier creation from SRR questionnaire

## Flow `[USER:2026-09-29]`
1. Requester submits the internal **Supplier Registration Request** (SRR) in Oracle (Redwood form + questionnaire).
2. SRR approval (*Manage Internal Supplier Registration Approvals*) `[ORA26C:implementing-procurement p.343]`.
3. On approval Oracle **creates the supplier**.
4. **INT959** completes the supplier details **directly in Oracle** from the questionnaire answers (profile fields, payment method, tax flags).
5. **Apex Portal is not involved in this (non-PO) path.** PO suppliers are onboarded separately through Apex → Oracle `[USER:2026-09-30]`; that path runs on **INT055A** `[USER:2026-09-30]`.

> Correction: `01-oracle-finance-spine` and `02-procure-to-pay-chain` describe INT959 as "Apex answers drive Oracle supplier profile". For the SRR path this is superseded `[USER:2026-09-29]`. The Apex → Oracle path is **INT055A**, not INT959 `[USER:2026-09-30]`.

## Known mapping behaviours `[CO:FIN-24137 register, dependencies, ER4 story]`
| Field | Behaviour |
|---|---|
| Payment method | Since Jan-2025 (FIN-18320) INT959 **end-dates every method except the one selected**. Change FIN-24752 (DEV1 built 19-Aug-2026): selected → **Default**, others remain **Active** (ER.3b). |
| Payment terms | Must match a pre-configured Oracle value or supplier creation fails (free-text terms rejected). |
| Address | Registration with no address → INT959 cannot create a payable (Remit-to) site; request fails or supplier can't be paid (ER.1 fix: address required at submission). |
| Tax Type | Mapped via lookup `LEGACY_ORACLE_TAX_PROFILE_MAPPING`; consumers under analysis (ER.4). INT055A uses `LEGACY_ORACLE_TAX_PROFILE_MAP` for the PO path — probably the same lookup, so a Tax Type change may affect both paths (Q-055A-6). |
| Tax Registration Number / Taxpayer ID / DUNS | At least one required today; needed for US 1099 and Brazil payment files; used for duplicate validation (ER.6 disputed). |
| Contact | Mandatory; produces junk contacts on ad hoc suppliers (ER.5). Which contact fields INT959 maps is unconfirmed (DP2). |

## Failure modes
Supplier creation fails on unmatched payment terms; address-less registrations; bank-account integration failures (historically concentrated in LATAM suppliers); missing/invalid city blocking structured-address payment formats. `[CO:02 §4 Stage 01, FIN-24137]`
